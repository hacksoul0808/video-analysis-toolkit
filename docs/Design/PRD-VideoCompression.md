## 2. 压缩参数（最终确认）

| 参数 | 值 | 说明 |
|------|:---|------|
| 分辨率 | `-2:480`（高度 480，宽度按比例） | 抖音短视频多为竖屏 9:16，效果约为 270x480 |
| 编码器 | `libx265` (H.265/HEVC) | 比 H.264 同画质省 ~30% 体积 |
| CRF | `32` | 明显压缩但内容可辨认 |
| 音频编码 | `aac` | 兼容性好 |
| 音频码率 | `64k` | 语音为主，够用 |
| 格式 | `.mp4`（保持原名） | 同名覆盖，前端无感 |
| 预估压缩比 | **80-90%** | 100MB → 10-20MB |

### 对应 FFmpeg 命令

```bash
ffmpeg -i input.mp4 -vf "scale=-2:480" -c:v libx265 -crf 32 -preset fast \
       -c:a aac -b:a 64k -movflags +faststart output.mp4
```

> `-preset fast` 牺牲少量压缩率换取编码速度（短视频场景下差距可忽略）。

## 3. 整体流程

### 3.1 新视频 Pipeline（自动）

```
下载(.mp4) → 转写 → AI分析 → 提取封面(cover.jpg) → 压缩替换(.mp4) → 更新 library.json
                                                              ↓
                                                    删除原始大文件，同名写入压缩版
```

### 3.2 历史视频批量压缩（一次性）

```
遍历 data/videos/*/ 下所有目录
  → 跳过无 .mp4 的目录
  → 跳过已标记 compressed: true 的目录
  → 提取封面 → 压缩替换 → 更新 library.json
```

批量压缩通过**独立脚本** `scripts/compress_existing.py` 触发，不通过 API（避免 HTTP 超时）。
